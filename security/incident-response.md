# EXAMORA — Security Incident Response & Breach Notification Procedure

## 1. Purpose & Scope

This document defines the operational incident response lifecycle for EXAMORA across authentication, PostgreSQL database (`Cloud SQL`), AI provider integrations, and student personal data governed by the **Digital Personal Data Protection (DPDP) Act, 2023**.

---

## 2. Severity Classification

| Severity | Definition | Response SLA | Examples |
| :--- | :--- | :--- | :--- |
| **SEV-1 (Critical)** | Confirmed unauthorized access to student PII, database credential leak, or remote code execution. | **Immediate (< 15 min)** | Leaked `GEMINI_API_KEY` or `SQL_PASSWORD`; cross-tenant IDOR data exposure. |
| **SEV-2 (High)** | Active brute-force campaign, sustained prompt injection bypass, or answer-key disclosure bug. | **< 1 Hour** | Automated credential stuffing; bypass of `correctAnswer` stripping. |
| **SEV-3 (Medium)** | Elevated rate-limit triggers, repeated malicious file upload attempts, or dependency vulnerability. | **< 4 Hours** | Repeated `MALICIOUS_FILE_REJECTED` alerts from a single actor. |
| **SEV-4 (Low)** | Isolated failed authentication attempts or minor CSP violation reports. | **< 24 Hours** | Expired token retries. |

---

## 3. Five-Phase Incident Response Workflow

### Phase 1: Detection & Triage
1. Monitor structured security logs generated by `logSecurityEvent()` in `src/security/securityEngine.ts` and `/api/security/status`.
2. Alert triggers include:
   - `RATE_LIMIT_TRIGGERED` (> 120 req/min per IP or > 10 AI generations/min per UID)
   - `PROMPT_INJECTION_DETECTED`
   - `MALICIOUS_FILE_REJECTED`
   - Repeated `AUTH_FAILURE` spikes

### Phase 2: Containment
1. **Compromised API Key (`GEMINI_API_KEY`)**:
   - Immediately revoke the key in Google Cloud / AI Studio Console and inject a rotated key via environment secrets.
2. **Compromised Database Credentials (`SQL_PASSWORD`)**:
   - Rotate the PostgreSQL `app_user` password in Cloud SQL IAM/Users and restart the service.
3. **Abusive User / Compromised Session**:
   - Revoke Firebase refresh tokens via `adminAuth.revokeRefreshTokens(uid)` and block the offending IP hash at the edge.

### Phase 3: Eradication
1. Identify the root cause in application code or dependency tree (`npm audit`, static analysis).
2. Patch the vulnerability and add a regression test in `security/security-tests.ts`.
3. Verify that all security tests pass (`npm run test:security`) and TypeScript compilation succeeds (`npm run lint`).

### Phase 4: Recovery
1. Deploy the patched build to production.
2. Verify database integrity across all 10 PostgreSQL tables (`users`, `consents`, `documents`, `topics`, `exams`, `questions`, `attempts`, `answers`, `results`, `topic_performance`).
3. Confirm normal telemetry and error rates.

### Phase 5: Post-Incident Review & DPDP Act 2023 Notification
1. Conduct a blameless post-mortem within 48 hours documenting root cause, timeline, and preventative controls.
2. **DPDP Act 2023 Personal Data Breach Notification**:
   - If any personal data (`fullName`, `email`, uploaded scans, or evaluation records) is involved in a confirmed breach, notify the **Data Protection Board of India** and affected Data Principals via the Data Protection & Grievance Officer (`privacy-grievance@examora.edu`) within the statutory window, detailing the nature of the breach, mitigation steps taken, and user remedies.
